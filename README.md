# Känguru Tutor — Supabase & PostgreSQL Socratic Support Tutor

An evidence-grounded, Socratic tutor that trains you to support-engineering mastery of
Supabase and PostgreSQL. Runs fully locally on a Supabase CLI stack, with the official
docs (`llms.txt` → `llms-full.txt` + `llms/*.txt`) as the primary RAG corpus, web search
only where freshness or community evidence is needed, and a text + Mermaid + voice UI.

It is designed to run two ways:

1. **Standalone** — `make up` starts local Supabase; `make dev` starts FastAPI + Vite.
2. **As a sub-module of the AuDHS Tutor** — `backend/tutor` is a FastAPI router and
   `frontend/src/tutor` is a React route; both mount into the existing app.

## Quickstart (macOS, Apple Silicon)

```bash
# prerequisites: Docker-compatible runtime (Docker Desktop / OrbStack), Node 22+, uv (Python 3.12 is fetched by uv)
# psql is NOT required: all DB scripts use psycopg.
cp .env.example .env
make reset                         # start stack, db reset (migrations + seed), lab DB, lab 01
make smoke                         # verify stack, schema, seed, search, lab roles, lab 01
make ingest                        # fills docs_chunk from llms.txt (ARGS="--dry-run" first)
make dev                           # FastAPI :8020 + Vite :5180 (API_PORT / WEB_PORT to change)
make dev-user ARGS=--print-token   # local dev learner + access token for curl against /tutor/*
make refresh-schedule              # weekly docs refresh via pg_cron + pg_net (backend must be running)
make tts                           # optional: local German server voice (Piper); set TUTOR_TTS=server in .env
```

`make help` lists every target. `supabase/seed.sql` is generated by `make seed` from
`docs/curriculum.yaml` and `labs/*/lab.yaml`; do not edit it by hand.

Then open the tutor, say "Hallo", and answer its single opening question.

## Non-negotiables (mirrored in CLAUDE.md)

- Factual accuracy and citations outrank persona and speed.
- Never claim to have run a command the learner ran. The tutor only executes SQL in the
  disposable **lab** database, never against the learner's real projects.
- No secrets in client code. `service_role` stays server-side.
- RLS is never disabled as a "fix"; only as a labelled diagnostic experiment in the lab.
